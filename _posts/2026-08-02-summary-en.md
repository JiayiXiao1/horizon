## [Stateless MCP 2.0 Reignites Interest, Inspires New Tools](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 8.0/10

Simon Willison reports that the release of MCP 2.0 (the 2026-07-28 Model Context Protocol specification) has renewed his interest in the protocol, leading him to build two new tools: mcp-explorer and datasette-mcp. The new stateless architecture simplifies client and server implementation by eliminating the need for session management. This update is significant because MCP is a widely adopted protocol for connecting AI agents to tools, and the stateless design makes it easier to build scalable web applications. It also addresses earlier criticisms that MCP was overly complex compared to simpler shell-based approaches, potentially broadening its adoption among developers. The stateless MCP specification allows a single HTTP request to invoke a tool, using headers like MCP-Protocol-Version and Mcp-Method, instead of the previous two-step initialization and session ID flow. Simon built mcp-explorer, a CLI tool for interactively probing MCP servers, and datasette-mcp, a plugin providing read-only SQL access to Datasette instances.

rss · Simon Willison · Jul 31, 23:13

**Background**: The Model Context Protocol (MCP) is an open standard introduced by Anthropic in November 2024 for exposing tools to LLM-powered agents. It gained massive popularity in 2025 but was later overshadowed by Anthropic's Skills feature, which allowed agents to use terminal and curl for more flexible operations. The new stateless version reduces complexity and improves scalability, making MCP more attractive again.

## [Ripgrep musl binaries segfault in large searches, kernel bug suspected](https://github.com/BurntSushi/ripgrep/issues/3494) ⭐️ 7.0/10

Ripgrep 15.2.0 built for x86_64-unknown-linux-musl occasionally crashes with SIGSEGV during very-large searches at high concurrency. The crash occurs in calloc() called from opendir(), due to a heap integrity assertion in musl's mallocng allocator. This issue affects users who rely on ripgrep's static musl binaries for performance and portability, especially in high-concurrency environments. The investigation highlights potential kernel-level memory management races and the performance drawbacks of musl's default allocator, which could influence future allocator choices in Rust projects. The crash is triggered by a heap integrity assertion in mallocng, and the root cause is suspected to be a memory-management race in Linux 7.0, though not yet confirmed by the mm subsystem. The affected version is ripgrep 15.2.0 (revision e89fff8) with PCRE2 10.45 and JIT enabled.

hackernews · throwaway2037 · Aug 1, 12:34 · [Discussion](https://news.ycombinator.com/item?id=49133889)

**Background**: Ripgrep is a popular command-line search tool written in Rust, often built with musl to produce static binaries for easy deployment. Musl's default allocator, mallocng, is known to have performance issues under multithreaded contention, and this bug may stem from an interaction between the allocator and the kernel's memory management. The Linux kernel provides various memory allocation APIs, and a race in the kernel's handling of memory could lead to such crashes.
