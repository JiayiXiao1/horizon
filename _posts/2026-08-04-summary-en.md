## [Manually Retyping LLM Code to Prevent Cognitive Debt](https://ankursethi.com/blog/prevent-cognitive-debt-by-manually-retyping-llm-generated-code/) ⭐️ 7.0/10

The article proposes that developers manually retype LLM-generated code instead of copy-pasting it, as a technique to prevent cognitive debt. This practice has sparked a lively community debate with 375 points and 314 comments. As AI-generated code becomes more prevalent, cognitive debt—the erosion of shared understanding—is a growing concern in software engineering. This technique offers a practical way for developers to maintain comprehension and ownership of code, potentially improving long-term maintainability and reducing risks. The article emphasizes that retyping code forces developers to engage with every character, creating a stronger memory and comprehension. Critics argue that this approach may negate the efficiency gains of using LLMs, while proponents compare it to rewriting Stack Overflow solutions to own the code.

hackernews · mpweiher · Aug 3, 09:32 · [Discussion](https://news.ycombinator.com/item?id=49153374)

**Background**: Cognitive debt is a term gaining traction in AI-driven development, referring to the debt that accumulates in developers' brains when they use AI-generated code without fully understanding it. Unlike technical debt, which is about code quality, cognitive debt affects developers' ability to make changes and go fast in the future. The practice of manually retyping code is a deliberate slowdown to ensure comprehension, similar to pair programming or test-driven development.
