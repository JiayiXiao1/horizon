## [sing-box uTLS Chrome Fingerprint Lacks Post-Quantum Key Exchange](https://sing-box.sagernet.org/configuration/shared/tls/) ⭐️ 8.0/10

sing-box's uTLS "chrome" fingerprint does not include the X25519MLKEM768 hybrid post-quantum key exchange curve, which Chrome 131+ uses as its default key exchange group. This creates a detectable difference in the ClientHello structure between sing-box and real Chrome. This discrepancy makes sing-box's TLS fingerprint distinguishable from real Chrome, potentially allowing advanced censorship systems to detect and block sing-box traffic. It highlights ongoing challenges in TLS fingerprint mimicry for censorship circumvention tools. sing-box previously offered a "chrome_pq" fingerprint that included post-quantum curves, but it was removed in version 1.10.0 due to incompatibility with the Reality protocol, causing a "nil ecdhe_key" error. The curve_preferences configuration option does include X25519MLKEM768, but that applies to the standard TLS engine, not the uTLS fingerprint module.

telegram · zaihuapd · Jul 1, 07:04

**Background**: TLS fingerprinting is a technique used by censors to identify and block proxy traffic by analyzing the ClientHello message structure. uTLS is a Go library that attempts to mimic browser TLS fingerprints, but has repeatedly been found to have vulnerabilities. Post-quantum key exchange like X25519MLKEM768 is being adopted by browsers to protect against future quantum computer attacks.
