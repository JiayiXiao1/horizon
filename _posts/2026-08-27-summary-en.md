## [vLLM v0.28.0 Boosts Kimi-K3 and DeepSeek V4 Performance](https://github.com/vllm-project/vllm/releases/tag/v0.28.0) ⭐️ 8.0/10

vLLM v0.28.0 was released with 584 commits from 270 contributors, introducing major performance optimizations for Kimi-K3 including Decode Context Parallel (DCP) support, fused FlashKDA kernels, and SiTU activation for MegaMoE. It also delivers end-to-end DeepSeek V4 support with sparse MLA, AMD Quark NVFP4, and ROCm enablement on gfx11 and gfx950. This release significantly enhances the inference performance of two leading open-source models, Kimi-K3 and DeepSeek V4, making vLLM a more compelling choice for production deployments. The optimizations, such as DCP and fused kernels, address critical bottlenecks in long-context and speculative decoding, benefiting developers and enterprises relying on high-throughput LLM serving. Key changes include a new default max_num_batched_tokens of 16384 (up from 8192), prefix caching enabled by default for Mamba models, and a raised Blackwell CUDA graph capture default of 1024. Breaking changes include migration of bitsandbytes support to an out-of-tree plugin, a Transformers bump to 5.15.0, and removal of deprecated features like calculate_kv_scales and override_attention_dtype.

**Background**: vLLM is a high-throughput, memory-efficient inference and serving engine for large language models, widely used in production. Decode Context Parallelism (DCP) shards KV cache by sequence length to ease memory pressure and improve throughput for long-context inference, while FlashKDA is a CUTLASS kernel developed by Moonshot AI for Kimi's linear attention. These technologies are crucial for handling the growing demands of long-context and multi-modal models.
